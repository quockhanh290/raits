## 4. The special decision: the Swing override **is** tracked

Two decision records sit side by side and now get opposite treatment, deliberately.

**`track1_go_live_confirmation.json` stays out of git.** The reason is written in `.gitignore`:
it is the file that arms the route. Restoring it from a checkout would arm a route, so it must
never be something git can create.

**`track1_swing_paper_override.json` is committed.** That reasoning does not transfer to it,
because it **cannot arm anything**:

```text
grants_orders              false
satisfies_shadow_evidence  false
parameter_promotion        false
evidence_promotion         false
```

All four are proven by tests that are in this same commit. Restoring the override from a checkout
restores a **scope** decision, never an **arming** one.

And it must be tracked, because the route *reads it at runtime* through
`track1_swing_paper_override.py`. If it were lost, paper scope would change silently, and the
signed risk acceptance with its four caveats exists nowhere else.
